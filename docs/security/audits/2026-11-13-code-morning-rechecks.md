## 2. Agent entry point `main.ts` (`4ddbede..bdda18b`) and fixes A to D (`bdda18b..4a312da`), security-auditor

**Entry point (bdda18b): BLOCK, 0 Critical, 2 High, 2 Medium, 3 Low** (only `main.ts`, `localdeps.ts` and the start script are new). **Fixes A to D (4a312da): BLOCK, 0 Critical, 2 High.** Good throughout: the key is read from the environment only (not argv), no key in errors or `LogEntry`, record file names are 64 lowercase hex (no traversal), receiver pinned to the strategy with `AGENT_METHODS` and no deposit, required config enforced, publication gated on `released()` (Closing or Closed only, fails closed).

- **HIGH-1 (not fixed at 4a312da): the record text is logged during `Running`.** `loop.ts` returns `record: text` in every `LogEntry` and `main.ts` writes each entry to stdout and `LOG_FILE`, so the exact decision record (state and decision, showing where the hidden stop-loss, take-profit and time bounds lie) is available to anyone with log access (a journal collector, a shared or served `LOG_FILE`, a follower without a viewing key), defeating T78. Log only the hash until `released`; test that no record text appears in the captured output.
- **HIGH-2 (new, same root): the held store is readable by any local user during `Running`:** `mkdirSync` and `writeFileSync` set no mode (umask-dependent, typically 755 and 644) and `main.ts` checks no permissions. Create the directory 0700 and files 0600 (flag `wx`), refuse to start if it is not owned by the process user or has group or other bits, and refuse equal or nested `HELD_DIR` and `RECORDS_DIR` (equal publishes everything immediately).
- **Fixed in 4a312da:** a restart after the strategy left `Running` now publishes (`run()` re-reads the held store after `released()`); write before send (`hold` runs before `chain.send`; a `hold` error sends nothing); `hold` and `publish` wrapped in `try/catch`; `readRecordFile` hashes every read against the file name; the paired open is re-verified (`verifyDecisionRecord` with strategy, open, range equality); the writer checks `evaluate == decision`. Earlier M2 (`readRecord` reads the published directory) fixed by wiring `heldDir`.
- **Still not fixed:** M1 (`RULES_FILE` not tied to the strategy's `rules_hash`), L1 (the localhost guard `^http:\/\/(127\.0\.0\.1|localhost):\d+` has no end anchor, `http://127.0.0.1:1@evil.example/` sends signed transactions in plaintext to `evil.example`; `realDeps` has no https check), L2 (`INTERVAL_S` not validated, `NaN` or 0 hammers the RPC; the comment names `AGENT_OBSERVE_INTERVAL_S`), L3 (`DCL` not checked against `get_config`), `real.ts` `head()`/`blockTimeNs` (raw `fetch`, no `res.ok`, JSON timestamp above 2^53 loses precision; the `released()` height comes from it), no SIGTERM handler, no EC-A06 key-log scan test.
- **New Medium:** the process can exit with records unpublished (`published` is set true after the first record and `stop()` returns it, so a failed second of three publishes ends the loop; stop only when every listed held hash is published). **Swap cap strands a legitimate agent after one transient failure (design tradeoff for the lead):** with commit 1371dc4 one failed `ft_transfer_call` receipt makes `swaps_used = 1`, `plan` then sends `agent_open` with unbalanced holdings, it is refused, the one-hour backoff retries hourly (each retry burns `max_actions_per_24h` and gas) and the strategy never opens until the creator closes (funds are not locked). - **New Low:** an orphan `<hash>.txt` can be published for an action that never reached the chain (the page must fetch only by on-chain hash); no `fsync` and a predictable temp name followed through a symlink in `writeRecordFile` (a crash can leave a zero-length file; a lost close record makes `observe` throw "close latch unknown" for ever); the paired open is gated on the swap's old state, not the current observation (also gate the sent range against `obs.state`).
