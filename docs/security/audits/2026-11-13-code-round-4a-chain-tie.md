## 1. Round 4a, security-auditor (`0860318..4ddbede`): fix before merge, 0 Critical, 0 High, 2 Medium, 4 Low (read only, no tests run)

**Failed exits leave no record: the earlier Medium (exit record growth) is fixed.** `drop_unproductive_exit` (`remove.rs` ~57-78, called from `end_remove` and the `resolve_stale` Remove arm, `funding.rs:493`) pops a failed or refused exit record only when it is the last record and its kind is `ExitRemove`, so a `ClosePosition` is never popped; it keeps `Ok`, `Unknown` (a lost remove), `Refused("own_position_gone")` and any close; the log is at most +1 while an exit is pending; exits are still never refused for storage; the rate stamp and lock are correct (the lock is released before the pop, a stale resolution still stamps the cooldown); no payout or fee goes uncounted (the fee counters change only in the `on_removed` success path, whose record is kept; a later exit reads a position as gone and clears it with no fees counted, the disclosed lower bound).

- **M1 (unverified): the page may lose evidence of a failed exit that held the lock.** A `Failed("remove")` still opens the settle window but its record is gone; if the page relies on records for lock intervals, the gap falls under the "outsiders, could not act" excuse or cannot be attributed. State in EC-W21 and INTERFACE that lock intervals are read only from the archival `get_lock` and `settle_window_class`, add a page fixture with a dropped failed exit, or keep the record when the stage reached `Removing`. I did not have web code that references `ExitRemove` read.
- **M2: the held-record store is not wired and breaks the agent's own reads.** `readRecord` (`real.ts:39-40`) reads the published `recordsDir`, but records are held privately until `Closing` and nothing connects `hold` or `publish` to `writeRecordFile` (no `main`). During `Running` the swap's record is unreadable, so the paired open silently falls back to an ordinary open with a fresh record and hash (D47 pairing never happens; the chain test passes only because its fake `readRecord` returns a record that was never held), and after a recorded `Ok` close `chain.ts:150` throws "the close latch is unknown" every round, so the agent can send nothing for the rest of the run and a restart does not help. Read held records from the private store (verified by hash), make `hold` required or default it to a private `writeRecordFile`, and test a swap followed by a paired open, and a recorded close followed by an `observe` without error.
- Low: popped indices are reused (`remove.rs:84`), so an indexer sees two `action` events with one `index` and different `op_id` (key on `op_id`); test gaps (a stale-lost exit in `ReadRound` or `Predicting` leaving no record, a failed `agent_close_position` keeping its record, an exit at `MAX_ACTIONS_STORED` leaving the log at the cap, the liquidity-0 `own_position_gone` branch); held records live in an in-memory `Map` and are lost on a restart or a crash before `Closing`, and one is held only if `sent !== null`; `hold` and `publish` are awaited without a `try/catch`, so a throw (disk full, an immutable file) kills `run`, and a `stop()` before `Closing` publishes nothing; the "published < held+1" test is trivial.
- Earlier open: **T80** (callback gas against a log near 60 records) is documented, with "a failed exit leaves no record" added to the mitigation, but still not measured (and "log near 40 in practice" assumes `max_actions_per_24h` of 6 over a 6-day run, not checked against the limits' maximum): open, disclosed, measure before any mainnet run. T76 (the close reads no price) and T77 (a lost add) unchanged and disclosed. Exit record growth: fixed.
- The new tests assert exact refusal results, the ratio bounds (9,960 and 10,000), the drift boundaries at ±15, 16, 30 and 31, the hold-back per token, the dust boundary and the zero minimum. EC-W19 is correctly narrowed to swap-step caps, a close goes to `missedClose` (D53); EC-C172 names its tests only generally.

## 2. Does the agent check decision == evaluate before sending (rules-verifier, read only at 4ddbede): fix before merge, 0 Critical, 3 High, 3 Medium, 1 Low

By construction yes (`plan` calls `evaluate` once, `decide.ts:40`; `round` hashes that same `obs.state`, `loop.ts:129`; `withinRules` and the `observed == state` check run before any send, `loop.ts:141-151`), but nothing asserts or recomputes the equality.

- **High, helper M-A still open:** `decisionRecordText` (`decision.ts:39-47`) never calls `evaluate` and `record()` (`decide.ts:59`) hashes any `Decision` it is given; a future caller or a changed `plan` can publish a readable record for a wrong decision and funds move on that hash. Make the writer throw unless `evaluate(rules, state)` equals the decision; the loop's fail-closed branch covers only exceptions, there is no explicit mismatch branch.
- **High, paired open:** `loop.ts:146-149` judges the swap's record only by `withinRules(rules, rd.state, rd.decision)`, not `evaluate == decision`, never checks `decisionHash(pair.text) === pair.hash` nor the record's strategy and rules hash, and `readRecordFile` (`records.ts:233`) returns the file without hashing it, so a swapped or corrupted `records/<hash>.txt` is accepted; apply `verifyDecisionRecord(text, pair.hash, rules, strategy)` on it. No round-level test of the paired path.
- **High, tests:** no agent test asserts the equality, removing `withinRules` from `round` breaks no test, and `loop.ts:156` ("outside the rules") is untested; only `verifyDecisionRecord` on the check side would catch a wrong decision, after the funds moved.
- The interface High (M-B and M-C) is not fixed at 4ddbede (the fix is the chain-tie branch below). Medium: the T78 hold breaks the agent's own reads (as in 1 M2), held records can be lost, and on the paired path the log shows the fresh decision with the swap's hash and record. Low: a close's `confirm_observed` is not compared with the state's `confirmFromBlock` (both come from `next.fromBlock` today).

## 3. `verifyDecisionRecordAgainstChain` (`bd26304..9b9c628`, security-auditor): **BLOCK**, 0 Critical, 1 High, 3 Medium, 3 Low

All 730 rules tests pass; four probes in the auditor's copy confirmed findings 1 and 3.

- **HIGH-1: the block and point tie is skipped for paired opens, and nothing requires the swap to be present** (`decision.ts` 232-238, the `!a.paired` guard; `ChainedAction.paired` 177-186). The function compares `observed.block` and `observed.point` only for actions with `paired === false`, nothing requires an unpaired action, and `paired` is a caller-supplied flag. Probe: a self-consistent invented record (invented holdings, principal and the rest) that `rebuilt` also agrees with, called with `actions = [{kind: "Open", observed: {block: 999, point: 5}, paired: true, left, right}]`, returns `matching` and the record's block and point are never compared with any chain observation; the same with `kind: "Swap", paired: true`. This happens when the page's grouping drops or misses the swap (outside the fetched range, a provider omits it) or mis-sets the flag, and it is exactly the invented-state hole the function is meant to close. Fix: require at least one unpaired `Swap` or `Open` whose observation equals the record's, else `cant_check`; refuse `paired: true` on any kind but `Open` as `not_matching`; best derive "paired" inside the function (an open is paired only if a swap in the list carries the hash and the open falls within `PAIR_WINDOW_S`); tests with only a paired open and with a paired swap.
- **MEDIUM-1:** the 3,600 s window and one open per swap are not checked, although T81 and EC-R35 imply they are (`ChainedAction` has no time fields): an open flagged paired days later, or two of them, read `matching` (unverified whether the contract enforces both; the contract only checks the same hash and a 3,600 s swap).
- **MEDIUM-2:** `INTERFACE.md:145` still says the page checks a record "only with `verifyDecisionRecord`" and `index.ts` still exports it, but it returns `ok: true` on an invented state; point both at `verifyDecisionRecordAgainstChain`, mark the old one insufficient, add a page test.
- **MEDIUM-3:** `rebuilt = null` and an action without `observed` throw `TypeError` (the page's catch sites handle only `RulesError`), and an unknown `kind` is treated as an open; validate shapes, `cant_check` for a bad shape, `not_matching` for an unknown kind.
- Low: a rebuilt field in conflict with the record (a `startedAtS` above `nowS`, a `confirmFromBlock` above the block) is reported `cant_check` where the truth is `not_matching`; `cant_check` is a truthy object with no `ok`, so a careless `switch` default or `status !== "not_matching"` could show a pass (use an exhaustive switch with a `never` check); `block`, `point` and `confirmFromBlock` are not in `rebuilt` (the page must rebuild `confirmFromBlock`; the point is bounded on chain by the drift check, `trade.rs:608`, whether the page also compares the pool at that block is unverified); `hold` and `done` decisions always return `cant_check`.
- Sound: canonical JSON comparison (bigint against decimal string, key order), a missing field gives `cant_check`, the open range is compared on swaps and on unpaired and paired opens, the kind mapping, the strategy, rules hash and hash checks, purity. The lead was sent HIGH-1 as blocking.
