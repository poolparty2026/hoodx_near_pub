## High (test-auditor)

**H1. The platform's held-back share is spendable by `agent_open` and no test notices** (`open.rs:574`). Removing `.saturating_sub(self.platform_owed(i).min(wallet))` passes all tests. `the_platform_share_is_not_spendable` (`tests_open.rs:863`) does not discriminate (the base side limits, so `add_x` is the same with or without the 100 USDC owed); the base-token side (`i = 1`) is never exercised through `agent_open`; `assert_ended` does not assert that fees, `paid_platform` or the owed counters are unchanged after a refusal. This is a missing test of a funds-flow rule; the code line is present. Add: owed positive on the quote side with the base side limiting, and again for `i = 1`, asserting exact amounts and unchanged counters.

## Medium

- **Removal can fail for ever, so settlement and every claim lock (security M1, unverified; contract-reviewer M3).** `settle.rs:252` refuses while `own_position` is set; the claims need `Closed` (`claims.rs:146,171,215`); D55 cut the "3 failed removes is stuck" rule. If DCL's `remove_liquidity` keeps reverting (pool not `Running`, a persistent min-amount mismatch, gas above 90 Tgas in a crowded range, T62), the principal, the creator's wallet funds and both claims stay locked. None of these causes is confirmed in the gates. Measure a removal in a paused pool and with 1,000 or more positions in range at 90 Tgas; then reinstate a bounded failure counter, or disclose as a v1 lock-in. **Status: the lead relayed that the user accepts this as a disclosed v1 risk; it is not logged as accepted until `THREAT_MODEL.md` carries the row (none on the backend branch yet).**
- **The close never compares the agent's observation with the chain (security M2; contract-reviewer M4).** No `get_pool` read in `agent_close_position`/`on_remove_reads` (cut by D55, against ARCH 5.7); `meta.observed` and `confirm_observed` are range and age checked only; the only guard is the minimums from DCL's own prediction at that moment, and an outsider can trigger `exit_remove` after the grace period. A lying agent with consistent fabricated observations can close early, and the slippage floor does not bound the loss to a price pushed before the read. Backend added T76 for this ("the close reads no price on chain"). Related Q15 and the anchor: keep a mainnet blocker.
- **Gas margins are thin and were measured with an almost empty log (contract-reviewer M1).** `agent_open` needs `MIN_GAS_OPEN` = 300 Tgas, the transaction ceiling; callbacks have about 10 Tgas of headroom (`on_open_reads` 220 handing out 210, `on_remove_predicted` 115 handing out 105, `on_open_added` 10); every callback reads and writes the whole `Strategy`, including up to 64 action records. A callback that runs out of gas reverts and its lock stays until `resolve_stale` (500 or more blocks); if it is `on_open_added`, the add succeeded, the stale arm sets `opened`, and the position becomes a gift (the platform's 5% lost); a lost remove loses the fees. Measure each callback with the log at 60 records.
- **Exit records can grow without bound (contract-reviewer M2, `remove.rs:250-255,61-99`).** Principle 8 says only exits that clear the position get an `actions` record; `exit_remove` always pushes one, and while a removal keeps failing each caller class adds a record every `min_action_interval_s`. Whole-state read and write cost grows, and the storage reserve counts at most `MAX_ACTIONS_STORED` + 48 + 8 + ring; exits may not be refused for storage, so writes eventually fail. Fix: write the full record only when the exit clears the position or changes fees; otherwise use the ring and a counter.
- **Removal fee semantics unverified (contract-reviewer M4, Part D).** If the removal's return excludes fees, `min(unclaimed, reported)` counts principal as fees and over-charges the creator; the sandbox only tested zero fees. Add a sandbox test with a swap crossing the range before the removal.
- **Test limit gaps (test-auditor):** `add_ratio` at 9,999, 10,000 and 10,001 (`open.rs:693`, `>=` to `>` survives); round-two drift at exactly 30 (`open.rs:671` survives, and the two drift checks are not told apart because the reference point equals the observed point in the fixtures); the dust boundary (`open.rs:608`); a round-two minimum of 0 on one side (`open.rs:710`, `&&` to `||` survives); round two has no `centring` or `nothing_to_add` test; the case named "centring" in the round-one refusals (`tests_open.rs:915-924`) actually fires the drift refusal; no test of `rules_json` storage stake against the 4,096 limit beyond the existing limit tests.
- **EC coverage:** about 20 applicable IDs are named by no test under `contracts/` (EC-C131, C123, C121, C143, C145, C162, C138, C150, C156, C112, C113, C139, C100, C08, C42, C122, C140, C147, C149, C153; several belong to later slices); slice 8 has no umbrella ID (suggest EC-C172); the sandbox tests name no EC ID and cover happy paths only (1 open test, 2 remove tests).

## Low

No `paused` check anywhere (EC-C48; track for the pause slice); a non-object `get_liquidity` answer (a string or an array) clears `own_position` as gone with no fees counted (`remove.rs:289-300`), treat only `null` or an object with a different `owner_id` as gone; the reserved log slots are not reserved from swaps (`open.rs:224`, `remove.rs:183`, `trade.rs:418`), so a stop-loss close can be refused `LIMIT: action log full` at 60 records and the page can count that against the creator; a round-two refusal always opens the settle window even if no deposit was sent; `pool.starts_with(quote)` should be an exact `"{quote}|"` prefix; `reveal` reuses `LIMIT: balance for registration`; `docs/INTERFACE.md` does not match the code (`agent_close_position` takes a third top-level `confirm_observed`, and `register_tokens`, `get_tokens_registered`, three events, the new Refused reasons, the Failed stages and the `open` and `remove` record fields are missing; ARCH 5.5 `new` row still says `register_tokens` is never called); the lost-add and D55 deviations (no auto-withdraw after a failed add, one-step `resolve_stale`, no slots read, two sequential removal read rounds) are disclosed in module headers; a lost add leaves a permanent undetectable position (T77); `GAS_DEPOSIT` 40 Tgas was measured only on native USDC and the sandbox wNEAR (Part M: failure at 20, success at 40); `exit_remove` consumes the rate slot before the read; `register_tokens` trusts any successful receipt (read `storage_balance_of` in the callback); two `let _ = name;` that discard the case label; `assert_ended` should also assert fees, paid amounts and owed counters unchanged; no proptest of `plan_add`'s ratio and minimum arithmetic.
