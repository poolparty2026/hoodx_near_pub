# Design audits of architecture revision 13 (daab7ec, D37)

Three fresh agents, scope only. Addressed in revision 14 (D38).

- **security-auditor: block** (Critical 1, High 3, Medium 5, Low 4).
  - C1: treating every in-pool position as the strategy's let anyone stop settlement, and every payout, by re-gifting tiny positions.
  - H1: gifts broke opens and rebalances (open blocked, swaps sized from tokens in gift positions, unbounded reads).
  - H2: funding above `max_principal` was kept and traded, beyond D4's cap.
  - H3: holdings read mid-operation miss tokens in flight, so the check page could report false missed stop losses.
  - M1: the creator could take the platform's owed amount after the window.
  - M2: fees from gifts raised `fees_collected`, letting an outsider force a take profit.
  - M3: outsider exits in `Closed` before the grace period.
  - M4: `need` never scaled to add amounts.
  - M5: stale edge cases. L1 to L4 as listed.
- **contract-reviewer: not ready** (High 2, Medium 4, Low 10).
  - H1: gifts block `settle` (as security C1).
  - H2: gifts make reads unbounded and size trades from unspendable tokens.
  - M1: a callback can't tell "not found" from other remove failures.
  - M2: the platform's per-token owed amount could be swapped away.
  - M3: `resolve_stale` left `fees_collected` and `paid_platform` unresolved while releasing the lock.
  - M4: Q15 still blocks M1. L1 to L10 as listed.
- **test-auditor: block.** 14 changed edge cases reviewed:
  - EC-C101's expected outcome was wrong: gifts raised the platform's cut.
  - About 30 unchanged cases contradicted revision 13, worst EC-C74 ("fees frozen").
  - Missing cases: fees counted twice after a lost remove; funding cap versus holdings; one claim at a time; `claim_platform` spam; the swap input cap; a claims property test; a gift before an open; quiet-block holdings on the check page; direct calls to the new callbacks.

| Finding | Resolution in revision 14 |
|---|---|
| Gifts block settle, break opens, raise fees, unbounded reads (sec C1, H1, M2; contract H1, H2) | `own_positions` from the strategy's own adds (at most 2); gifts ignored, removable by anyone, no fees; reads bounded; EC-C107, C121, C122 |
| Lost adds without the full list | `unknown_add` with `before` and `expected_liquidity`; adopted on exactly one match; EC-C112 |
| Funding over the cap traded (sec H2) | Refunded in `Open`; each deploy capped at `max_principal`; EC-C03, C116 |
| Tokens in flight (sec H3) | Holdings only at quiet blocks; round 2 parks until the remove's payout is visible; EC-W21 |
| Platform share (sec M1, contract M2) | `platform_owed` held back from swaps and deposits; every `claim_creator` pays the platform first; EC-C114, C119 |
| Exit timing for outsiders (sec M3) | Outsiders only after `run_end + exit_grace` in every status |
| `need` scaling (sec M4) | `scaleNeed` in `packages/rules`, recorded as `add_amounts` |
| "Not found" classification (contract M1) | A follow-up `get_liquidity` read |
| `resolve_stale` (contract M3, sec L1) | `StaleRead` stage holds the lock until its read; fees once (EC-C115); a lost claim is treated as paid; every token-moving method waits out the cooldown |
| Stale and missing edge cases (test audit) | About 40 rows retired, rewritten or marked pending Q15; EC-C115 to C122 and EC-W21 added |
| Lows | `exit_*` take the lock; no `nft_transfer`; `set_agent` aborts parked chains; `dust_threshold` exactly two tokens; storage headroom; restore writes exempt; state list completed |
