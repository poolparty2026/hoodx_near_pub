## Security-auditor
- **M1 (urgent, feature-breaking).** CSP `connect-src` in `apps/web/src/proxy.ts:14` allows only 'self', free.rpc.fastnear.com and the records hosts; the code calls rpc.testnet.near.org (chain.ts:9, wallet.ts:8) and test.rpc.fastnear.com (chain.ts:9). On Vercel every view and transaction is blocked. Fix: add the exact testnet RPC origins; test that the CSP origins cover `TESTNET_RPCS` and `TESTNET_RPC`; fix the stale "RPC origin is fixed" comment. Fails closed, no security impact.
- **M2.** `buy()` (flow.ts:29-33, FollowLive.tsx:21-26) generates the pair then awaits the call. If the call throws after the tx landed (RPC timeout, final-status wait), or the tab closes/reloads before backup, the secret key is lost; the deliverer seals to a pubkey nobody holds, the sale is Released, refund closed. Price spent for nothing. Fix: show the backup before sending, return the pair even on throw, `beforeunload`, `loadFollow` after an error with a "sale may exist" message; test a wallet that rejects after succeeding.
- **M3.** `secret` state cleared only on success (FollowLive.tsx:31-41); key pasted into a hosted page, ~100 transitive packages in the bundle. Fix: clear in `finally`, warn, refuse account ids not ending `.testnet`, test.
- **M4.** Deposit comes from the contract's own `key_price` view; the `strategy` URL segment is untrusted. A hostile testnet contract can make the wallet attach any amount. Fix: cap the price at a few NEAR, show the exact amount on the button, check the strategy id is a testnet account, test 10^30 is refused with nothing sent.
- Low: L1 100 TGas and test.rpc.fastnear.com are GUESS (wallet.ts:9, chain.ts:7), not in docs/gates; L2 chain guard asks the same RPC (pin the URL too; "checked before every call" overstates); L3 account ids unvalidated; L4 `importSecret` does not check the pubkey belongs to the secret (fails safe); L5 two providers at different heights give a false "disagree" right after a buy (fail closed, add retry); L6 client `Date.now()` drives the refund button (cosmetic, contract enforces).
- S1 supply chain: near-api-js 7.5.3 adds ~112 packages (sha512, no git/http sources seen); install scripts unchecked. Run `pnpm install --frozen-lockfile --ignore-scripts`, review `pnpm why`. Unverified.
- Sound: base64 canonical check, rules hash verified twice, pubkey match before opening, `buyState` from views only. `UnlockedView` not in the diff, not checked.

## test-auditor
- **B1 (merge order).** At d9ca8a1, `docs/INTERFACE.md` has no section 9 and says the key methods are "Not in v1 (D55)", and `contracts/` has no `buy_viewing_key`, `get_key_params`, `get_key_sale`. That is because the spec and contract live on `contract/viewing-keys` (a509172), reviewed in the contract audit. Treat as a dependency, not a web defect, but: the web view shapes, `BUY_REFUSALS` strings (flow.ts:32-35) and deposit rule are unverified against the real contract until merged. Needed: a contract-shape fixture test loading recorded `get_key_params`, `get_key_sale`, `get_config` output from the merged contract, and the stub test labelled "Evidence (not a contract test)".
- **B2.** No test names an EC-K ID (only EC-W04, EC-W11, EC-W08). `BUY_REFUSALS` is never exercised. Add tagged tests for EC-K01 (mismatched pair then `does_not_open`), EC-K03/K04 (deliverer seals a wrong key, trust text shown), a loop over `BUY_REFUSALS` reaching `setError` verbatim (component test). EC-K02 is untested because `importSecret` accepts any 64-hex pair.
- **High.** H1 `loadFollow` only tested with agreeing providers; mutating `viewAgreed(a, b, ..., "get_config")` to `(a, a)` survives, so one dishonest RPC could serve a tampered ciphertext or sealed key (add per-method disagreement tests, EC-W08). H2 default RPC URLs and `realAccount`/`rpcView` untested. H3 wallet args asserted with `toMatchObject` (gas, extra args pass); use `toEqual`, cover both methods. H4 `buy()` has no state guard and nothing tests sold-out, existing sale, price mismatch, all-zero key through `buy()`; `doBuy`/`doRefund` untested. H5 secret handling in `FollowLive` untested (clear after buy/refund, no secret in DOM/console/error).
- Medium: view-parser limits (u32/u64/u128 max and max+1, account id 64/65, `sold > max`), `parseConfigForFollow` edges (padding, URL-safe base64, whitespace, empty, >8000 which is dead code), `buyState` Refunded/Released/deadline, `openAndVerify` wrong-length key, e2e stub happy path only (assert `buyer_pubkey` equals the generated key), `importSecret` CRLF/uppercase/mismatch.
- Low: XSS payload variety in `UnlockedView`, strategy-name normalisation, unseeded randomness, no property tests (fast-check candidates listed by the auditor).
