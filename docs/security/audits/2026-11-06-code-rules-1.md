# Code audits of the skeleton and packages/rules, 6 November 2026

- **Scope:** git range `3ec0234..12f6efd`: the repo skeleton, CI and `packages/rules`. It was started early under D24.
- **Auditors:** three fresh instances: `security-auditor`, `test-auditor` and `rules-verifier`. All read-only.
- **Incident:** the security auditor ran `git checkout`, which left the shared checkout on a detached HEAD. The next commit (`2cbb805`, gate 4) was then not on the branch or on GitHub until it was noticed and fast-forwarded. No work was lost. Every audit agent now carries a rule never to change git state.

## Open design questions (for the co-leads, before the agent or check page is built)

1. **How holdings get into both tokens.** With USDC-only deposits and no swaps (D26), a range containing the price can barely be funded. Options: deposits in both tokens, or a deterministic swap-to-target-ratio step whose size the library computes.
2. **Which state judges an action.** The contract centres on its reference price; the library on the observed point. One must be chosen.
3. **Size envelope.** Opens and rebalances have no amounts in `Decision`, so a near-empty add passes.
4. **How a rebalance is recorded.** The contract refuses a reused decision hash, but a rebalance is two locked operations.
5. **Missed-action detection and a shared state builder** belong in the library, not in each caller.

**Price accuracy found while checking vectors:** `priceQ128` is at or below the true 1.0001^point, within 2.1e-33 relative over 0 to 800,000. (Corrected after the re-audit: this held for points >= 0 only; the reciprocal path for negative points lost up to 3e-5 and has been removed.) So the swap never overshoots against the library's own price, and against the true price it can overshoot by at most about 1e-32 relative (112 units at u128::MAX). Harmless, and documented in the checker.

## Further open design questions

6. **Stop loss valuation (H-1).** Value at spot with a persistence requirement (for example the condition must hold at the observed block and at the contract's own read), or keep the anchor and have the check page flag stale anchors. A manipulated close only removes liquidity (D13), so spot valuation's harm is bounded.
7. **Swap step limits (swap M2).** Exempt the deterministic swap from `max_swap_value`, bounded instead by the anchor deviation and its own cap, or cap it and add a partial-funding rule.
