| Finding | Resolution in revision 23 |
|---|---|
| Security H-1, contract H-1, test B1: any Open record, even a refused one, used up the run's single open; an outsider could cause it | `opened` is set only by a successful add, an adopt or a recorded `unknown_add` (cleared by a dismissal); refused and failed opens can be retried, depositing only the shortfall; EC-C159 |
| Security H-2, contract H-2: a call relayed through the caller's own contract (X signs to X) passes the direct-call rule but has no transaction to the strategy | `call_blocks` records the signer; transactions are found by signer, any receiver, and kept if their tree contains the strategy's receipt; an unfindable transaction (RPC failure only) gives "can't check" for agent actions too, except the agent's own call; EC-C157, EC-W21 |
| Security M-1, contract L-3: swap churn without rebalance | At most `MAX_SWAPS_PER_RUN` (2) swaps with output per run; EC-C160; T3 restated |
| Security M-2, contract L-4: the v1 schema still required a rebalance policy | v1's schema has no `rebalance` field (in the rules pull request, EC-R29) |
| Contract M-1: "parallel views run in one block" unverified | The add also needs its predict to use nearly all of `add_amounts`, which bounds the price without that assumption; the assumption is a 5.11 item; EC-C161 |
| Contract M-2, security L-1, test B2: the swap-open pair against the exact target range and the action interval | The Open is judged at its own observation; reuse allowed after an `Ok` Swap with output, any range, within `PAIR_WINDOW_S`; the paired open is exempt from the interval, not the 24-hour count; EC-C158 |
| Contract M-3: swap-gas griefing blocks every v1 run | Disclosed as a v1 liveness limit in T62; two-token funding a co-lead decision (5.11) |
| Test B3: the `agent_continue` settle-window refusal | Removed: no operation waits for a window |
| Security L-2, contract L-2, L-3 (sec): dust adds, short deposits | `Refused(nothing_to_add)`, `Refused(deposit_short)`; EC-C161 |
| Security L-4: `agent_swap` hash rule | Always a new hash |
| Security L-5: low `max_actions_per_24h` | At least 4 |
| Contract L-1: reserve oversized for v1 | One record per trading lock plus 32; about 7 NEAR for 30 days at 6 a day, 32 NEAR at the bounds |
| Test F1 to F10, security L-6 | EC-C38 exception; one global first-check order (EC-C08, C124); messages per stage in EC-C158; hash cases; EC-C106 failure cases; EC-C143 sequence; leftovers in EC-W21 and 5.11; `no_swap_needed` outcome; EC-C29, C09, C31 messages; `PAIR_WINDOW_S` as the pair tolerance; `claim_fees` mapping; the quote round always re-checks drift |
