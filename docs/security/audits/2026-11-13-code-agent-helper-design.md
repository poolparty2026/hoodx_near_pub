**Security, open:**

- **M-B** a record can verify for the wrong sequence slot: no sequence number or previous head in the record, the contract checks only that `chain_head` is 64 hex, so a dishonest agent can attach an old valid record's hash (same strategy, also an open or close) to a new action; only a page that compares block and `nowS` with the action's own observation and recomputes the chain rejects it, and neither lives in the shared function. Add `prev` or an index and take the expected `observedBlock` and `prev` in `verifyDecisionRecord`.
- **M-C** `verifyDecisionRecord` returns `ok:true` on the agent's own state (inflated holdings, lower `nowS`): see the design finding in section 5; add `expectedState` or return `stateUnanchored`.
- **M-D** T78 is enforced only in docs: nothing stops records reaching a host during the run (the agent writes `<hash>.txt` files as it goes), which would disclose the stop-loss, take-profit and time bounds. Write records only after observing `Closing` or later, or hold only hashes until then. Unverified: whether the log is ever public.
- Low: `evaluate` can throw inside `verifyDecisionRecord` for rules not from `validateRules`; holdings reads carry no block (mixed blocks undetectable); `positionPieces` returns unclaimed fees that `tokenHoldings` ignores (the 5.11 double count, gate 3 Part D, **unverified**: do not claim EC-R34 closes it); T76 and T77 are absent or out of order next to T78.

## 5. Interface design re-check (`INTERFACE.md`: freeze a122e90 plus the paragraphs on 0860318): BLOCK

security-auditor: 0 Critical, **1 High**, 3 Medium, 6 Low. The text matches the contract for `register_tokens`, `get_tokens_registered`, the events, every Refused reason and Failed stage, `agent_close_position(position, meta, confirm_observed)`, `reveal` and `agent_open` (the round 4a omissions are now documented).

- **H1 (design, concrete path).** INTERFACE tells the page to check a record "only with `verifyDecisionRecord`", which checks the SHA-256, the canonical form, the strategy, the rules hash and that `evaluate(rules, record.state)` equals the record's decision, but never requires `record.state` to be tied to chain data. A compromised agent sends a real close or open (the contract never compares `observed` with the pool for a close, T76), writes a record whose state (point, block, `nowS`, holdings, fees, principal, position, `closedBy`, `valuationPoint`) is invented so that `evaluate` returns `close/stop_loss` or `open L,R`, and sends its SHA-256; after the reveal the page runs `verifyDecisionRecord`, gets `ok:true` and shows "matching". Funds are not lost (public limits still apply) but the "followed the rules" verdict is false. Same defect as helper security M-C. Fix: INTERFACE and the page rule must require `record.state.block` and `.point` to equal the on-chain `meta.observed`, an `open` decision's left and right to equal the record's on-chain points, and every other state field to be rebuilt from chain data at `observed.block` and compared (mismatch is "not matching"; a field that cannot be rebuilt, such as `valuationPoint` under Q15, is "can't check"); add `verifyDecisionRecordAgainstChain` to `packages/rules`; tests where a self-consistent record carries a wrong `state.point`, `holdings` or `block`, or an open range that differs from the on-chain range. Sent to the lead as blocking; a targeted re-check follows the fix.
- M1: the paired-open paragraph contradicts `ARCHITECTURE.md` 158 (the open is judged at its own observation): the contract requires only the same hash, a swap under 3,600 s old and fresh public-limit checks, so for up to an hour the agent can open any range within the limits with no rules evaluation at that time. Reconcile the texts, add a THREAT_MODEL item and an EDGE_CASES entry (an open whose on-chain range differs from the swap decision's range is "not matching"), and a test. M2: INTERFACE still does not say that `Open: Unknown` means "possibly stranded" and must never show a pass (T77; a 5.11 item, since gate 3 line 80 confirms a plain `<pool>#<n>` id). M3: removal fees cannot be checked from public data (no read block): say "can't check" until a round trip reconciles them, or store the read block.
- Low: stale lines remain in the header ("freezes it once ... settled"), "Built, growing" and "inputs not strict yet"; `get_deploy_block` and `get_last_payout_callback_block` are mislabelled Proposed and Planned; the null-head policy is unspecified (a null head on a trading record should be "not matching", `ExitRemove` excluded from the chain); `ExitRemove`'s empty `decision_hash` breaks the "64 lowercase hex" rule and `reveal` reuses `LIMIT: balance for registration` (F6, unfixed); "Publication from `Closing`" is ambiguous (the creator can reveal during `Running`; a creator who never reveals means "can't check", never "matching"); the paired-open, chain-head and publication paragraphs changed inside the rules and agent branches, not in their own interface pull request (CLAUDE.md).
- Earlier F1 (decision hash and chain definition) fixed; F2 (removal fees) partly; F3 (stale text) partly; F4 (lost add) not fixed in INTERFACE; F5 (exit caller rule) fixed; F6 not fixed.
