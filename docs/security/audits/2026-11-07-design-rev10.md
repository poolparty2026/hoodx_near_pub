# Design audit: architecture revision 10 (06661fb)

Sections 4 and 5 of `docs/ARCHITECTURE.md`. Fresh `contract-reviewer` and `security-auditor`, scope only. There is no `contracts/` code yet, so this is a design review.

## contract-reviewer (verdict: not ready; High 5, Medium 9, Low 13)

| ID | Severity | Finding | Resolution |
|---|---|---|---|
| H1 | High | A swap DCL refuses (price past `min_out`, pool paused) refunds everything, yet the table still credits `min_out`, so `held` overstates the balance (EC-C87) | Open, revision 11: credit only when the input was fully used; `used == 0` is `Failed(swap)` with no credit; define partial use; new EC |
| H2 | High | The lost-and-found subtraction assumes DCL records a failed payout before our callback reads `get_lostfound`; for remove, swap and `withdraw_lostfound` that ordering is unverified and probably wrong | Open, revision 11: blocking sandbox item; until confirmed, credit `min(reported, ft_balance_of delta)` |
| H3 | High | Debits applied inside callbacks are lost when a callback runs out of gas or panics, so `held` overcounts | Open, revision 11: debit before each outgoing promise, credit back only what is refunded |
| H4 | High | The two-step rebalance lets anyone call `agent_rebalance_finish` after `stale_after_blocks`, so outsiders trade, contradicting principle 5 | Open, revision 11: only the agent finishes, before a deadline; after it anyone may only abort |
| H5 | High | Read order is impossible as written (the quote needs the direction, which needs `predict_add_liquidity`, which step 2 doesn't list); gas is undercounted, and step B may itself exceed 300 Tgas | Open, revision 11: exact stage list, nested gas sums measured in the sandbox, a general `Pending { op_id, stage }` state machine resumed only by the agent |
| M1 | Medium | Claims and `held` contradict each other (`sweep_residual`, `resolve_stale_claim` double count, underflow) | Open: one convention, saturating subtraction, frozen `platform_cut` |
| M2 | Medium | Pause and `run_end` re-checks also block the recovery `withdraw_asset` | Open: re-checks gate only risk-adding stages; a stop after a deposit always withdraws |
| M3 | Medium | Refunds of unused tokens after an add are not credited | Open: conservative credit; sandbox check of refund path and unwrapping |
| M4 | Medium | `withdraw_lostfound` and `skip_unwrap_near` unverified | Open: sandbox item; credit by wNEAR balance delta until confirmed |
| M5 | Medium | Callbacks not tied to an operation id; `#[private]` not stated | Open: `#[private]`, `(op_id, stage)` checked against the lock |
| M6 | Medium | Nothing drops an unmatched `Unknown` add, so settle can block forever | Open: `close()` resolves each entry from `list_liquidities` |
| M7 | Medium | Settle needs Rhea balances below dust; a blacklisting token blocks payouts forever | Open: after a further grace period settle ignores lost-and-found and internal balances |
| M8 | Medium | Gifted dust positions can exhaust `max_outsider_records`; DCL storage per gifted position unverified | Open: cap excludes snapshot work; non-snapshot removes write an event only; sandbox item |
| M9 | Medium | `storage_reserve` formula undercounts; no way to return surplus reserve NEAR | Open: corrected formula, `withdraw_storage_surplus`, storage invariant |
| L1 to L13 | Low | Fee credit from the credited amount; probe units; two-step reservations; `allowed_tokens` field; direct transfers in `Closing`; agent `exit_remove` vs A14; `set_agent` separation; `withdraw()` debit; `dust_threshold` bound; stale cache vs outsider exits; late add after `resolve_stale`; text drift; NEP-297 event names | Open, revision 11 |

Checks that pass: attached deposits match the gate; the agent never attaches a deposit; `claim` raises `paid` before transferring; `sweep` is locked; key sales move NEAR once; `reveal` is checked against the hash; payouts go only to known accounts; `platform_cut` is capped by `held`.

New unverified Rhea behaviour for section 5.11: payout ordering against our callback (remove, swap, `withdraw_lostfound`); `withdraw_lostfound` with `skip_unwrap_near`; DCL storage for gifted positions.

## security-auditor (verdict: block; High 4, Medium 6, Low 7)

| ID | Severity | Finding | Resolution |
|---|---|---|---|
| H1 | High | `sweep_residual` regressed from "after both claims are paid" to "no claim in flight"; a gas-starved inbound `ft_transfer_call` inflates the balance read and its refund then draws on owed funds (EC-C91's premise is wrong) | Open, revision 11: restore "refused until every claim of the token is paid and none in flight"; correct EC-C91; sandbox test |
